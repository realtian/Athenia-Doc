Every configurable behaviour in OpenClaw on Cloudflare is controlled through Wrangler secrets — encrypted environment variables stored in Cloudflare's platform and injected into your Worker at runtime. You set each one with the same command pattern:

```bash
npx wrangler secret put <SECRET_NAME>
```

Wrangler will prompt you to type or paste the value. Secrets are never stored in your source code or `wrangler.jsonc`. After setting any secret, redeploy with `npm run deploy` for the change to take effect.

<Note>
  Secrets marked **Yes\*** are conditionally required — they are required only when you are using a specific feature or provider. The table below explains exactly which condition applies to each.
</Note>

## AI Provider

At least one of the following AI provider configurations must be set before OpenClaw will start. Cloudflare AI Gateway takes precedence over all direct keys when all three gateway secrets are present.

<ParamField path="CLOUDFLARE_AI_GATEWAY_API_KEY" type="string" required>
  **Required if using AI Gateway.** Your AI provider's API key (e.g., your Anthropic API key), passed through the Cloudflare AI Gateway to the upstream provider. Must match the provider you're targeting — the gateway does not supply its own credentials.

  Requires `CF_AI_GATEWAY_ACCOUNT_ID` and `CF_AI_GATEWAY_GATEWAY_ID` to also be set.
</ParamField>

<ParamField path="CF_AI_GATEWAY_ACCOUNT_ID" type="string" required>
  **Required if using AI Gateway.** Your Cloudflare account ID. Used to construct the gateway URL: `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/...`
</ParamField>

<ParamField path="CF_AI_GATEWAY_GATEWAY_ID" type="string" required>
  **Required if using AI Gateway.** Your AI Gateway ID, visible on the gateway overview page in the Cloudflare dashboard. Used alongside your account ID to build the gateway URL.
</ParamField>

<ParamField path="CF_AI_GATEWAY_MODEL" type="string">
  **Optional.** Overrides the default model (Anthropic Claude Sonnet 4.5) when using AI Gateway. Specify as `provider/model-id`, for example:

  - `workers-ai/@cf/meta/llama-3.3-70b-instruct-fp8-fast`
  - `openai/gpt-4o`
  - `anthropic/claude-sonnet-4-5`
  - `groq/llama-3.3-70b`
</ParamField>

<ParamField path="ANTHROPIC_API_KEY" type="string" required>
  **Required if not using AI Gateway.** Direct Anthropic API key for Claude access. Obtain one from [console.anthropic.com](https://console.anthropic.com/). When Cloudflare AI Gateway is configured, this key is ignored in favour of `CLOUDFLARE_AI_GATEWAY_API_KEY`.
</ParamField>

<ParamField path="ANTHROPIC_BASE_URL" type="string">
  **Optional.** Custom base URL for the Anthropic API. Useful if you are routing Anthropic requests through your own proxy. Leave unset to use the default `https://api.anthropic.com`.
</ParamField>

<ParamField path="OPENAI_API_KEY" type="string">
  **Optional.** OpenAI API key, used as an alternative AI provider when Anthropic is not configured. Obtain one from [platform.openai.com](https://platform.openai.com/).
</ParamField>

<ParamField path="AI_GATEWAY_API_KEY" type="string">
  **Deprecated.** Legacy AI Gateway API key. Use `CLOUDFLARE_AI_GATEWAY_API_KEY` instead. Still supported for backward compatibility.
</ParamField>

<ParamField path="AI_GATEWAY_BASE_URL" type="string">
  **Deprecated.** Legacy AI Gateway endpoint URL. Use the three `CF_AI_GATEWAY_*` secrets instead. Still supported for backward compatibility.
</ParamField>

## Authentication

These secrets control access to the Control UI and the admin panel. All three are required for a production deployment.

<ParamField path="MOLTBOT_GATEWAY_TOKEN" type="string" required>
  **Always required.** A shared secret token used to access the Control UI. Pass it as a query parameter when opening the UI: `https://your-worker.workers.dev/?token=YOUR_TOKEN`

  Generate a secure value before deploying:

  ```bash
  export MOLTBOT_GATEWAY_TOKEN=$(openssl rand -hex 32)
  echo "Your gateway token: $MOLTBOT_GATEWAY_TOKEN"
  echo "$MOLTBOT_GATEWAY_TOKEN" | npx wrangler secret put MOLTBOT_GATEWAY_TOKEN
  ```

  Keep this token private. Even with a valid token, new devices still require approval via the admin UI at `/_admin/`.
</ParamField>

<ParamField path="CF_ACCESS_TEAM_DOMAIN" type="string" required>
  **Required for admin UI.** Your Cloudflare Access team domain, in the form `myteam.cloudflareaccess.com`. The worker uses this to validate JWT tokens issued by Cloudflare Access for the `/_admin/`, `/api/*`, and `/debug/*` routes.

  Find your team domain in the [Zero Trust Dashboard](https://one.dash.cloudflare.com/) under **Settings** → **Custom Pages**.
</ParamField>

<ParamField path="CF_ACCESS_AUD" type="string" required>
  **Required for admin UI.** The Application Audience (AUD) tag from your Cloudflare Access application. Used to verify that incoming JWTs were issued specifically for this worker, preventing token reuse across applications.

  Copy this value from **Zero Trust** → **Access** → **Applications** → your application's settings.
</ParamField>

## Developer / Debug

These secrets are intended for local development and troubleshooting only. Do not enable them in production.

<ParamField path="DEV_MODE" type="string">
  **Optional. Local dev only.** Set to `true` to skip Cloudflare Access authentication and bypass device pairing entirely. This allows you to use the admin UI and Control UI without valid Access tokens or paired devices.

  <Warning>
    Never set `DEV_MODE=true` in production. It removes all authentication layers and exposes your worker to anyone who can reach it.
  </Warning>

  For local development, set this in your `.dev.vars` file rather than as a Wrangler secret:

  ```bash
  DEV_MODE=true
  ```
</ParamField>

<ParamField path="DEBUG_ROUTES" type="string">
  **Optional.** Set to `true` to enable the `/debug/*` endpoints. When enabled, the following routes become available (all protected by Cloudflare Access):

  - `GET /debug/processes` — list all container processes
  - `GET /debug/logs?id=<process_id>` — get logs for a specific process
  - `GET /debug/version` — container and OpenClaw version info
</ParamField>

<ParamField path="SANDBOX_SLEEP_AFTER" type="string">
  **Optional.** Controls how long the sandbox container stays alive when idle. Accepts `never` (default) or a duration string such as `10m`, `30m`, or `1h`.

  The default `never` is recommended because cold starts take 1–2 minutes. If you use this worker infrequently, setting `10m` can significantly reduce compute costs. When R2 storage is configured, your paired devices and data survive restarts.

  ```bash
  npx wrangler secret put SANDBOX_SLEEP_AFTER
  # Enter: 10m
  ```
</ParamField>

## Persistent Storage / R2

These three secrets enable R2-backed persistent storage. All three must be set together — if any one is missing, R2 will not be mounted. See the [Persistent Storage guide](/configuration/persistent-storage) for setup instructions.

<ParamField path="R2_ACCESS_KEY_ID" type="string">
  **Optional (required for R2 persistence).** The Access Key ID from your R2 API token. Create the token in the Cloudflare dashboard under **R2** → **Overview** → **Manage R2 API Tokens** with **Object Read & Write** permissions on the `moltbot-data` bucket.
</ParamField>

<ParamField path="R2_SECRET_ACCESS_KEY" type="string">
  **Optional (required for R2 persistence).** The Secret Access Key paired with `R2_ACCESS_KEY_ID`. This is shown only once when you create the R2 API token — copy it immediately.
</ParamField>

<ParamField path="CF_ACCOUNT_ID" type="string">
  **Optional (required for R2 persistence).** Your Cloudflare account ID, used to construct the R2 S3-compatible endpoint URL. Find it in the [Cloudflare Dashboard](https://dash.cloudflare.com/) by clicking the three dots next to your account name and selecting **Copy Account ID**.

  <Note>
    This is separate from `CF_AI_GATEWAY_ACCOUNT_ID` — both reference the same Cloudflare account ID value, but they are stored as independent secrets.
  </Note>
</ParamField>

## Chat Channels

All chat channel secrets are optional. After setting any of them, run `npm run deploy` to register the bot with the platform. See the individual platform sections in the [AI Providers guide](/configuration/ai-providers) for context.

<ParamField path="TELEGRAM_BOT_TOKEN" type="string">
  **Optional.** Token for your Telegram bot. Obtain one from [@BotFather](https://t.me/BotFather) on Telegram.
</ParamField>

<ParamField path="TELEGRAM_DM_POLICY" type="string">
  **Optional.** Controls how direct messages to your Telegram bot are handled. Accepts `pairing` (default) or `open`.

  - `pairing` — new devices must be approved via the admin UI before they can interact with the assistant.
  - `open` — any Telegram user who messages the bot can interact immediately, with no approval required.
</ParamField>

<ParamField path="DISCORD_BOT_TOKEN" type="string">
  **Optional.** Token for your Discord bot application.
</ParamField>

<ParamField path="DISCORD_DM_POLICY" type="string">
  **Optional.** Controls how Discord direct messages are handled. Accepts `pairing` (default) or `open`. Behaves identically to `TELEGRAM_DM_POLICY`.
</ParamField>

<ParamField path="SLACK_BOT_TOKEN" type="string">
  **Optional.** The OAuth bot token for your Slack app (begins with `xoxb-`).
</ParamField>

<ParamField path="SLACK_APP_TOKEN" type="string">
  **Optional.** The app-level token for your Slack app (begins with `xapp-`). Required in addition to `SLACK_BOT_TOKEN` for Socket Mode connectivity.
</ParamField>

## Browser Automation

These secrets enable the Chrome DevTools Protocol (CDP) shim that lets OpenClaw control a headless browser for web scraping, screenshots, and automated tasks. Both must be set together.

<ParamField path="CDP_SECRET" type="string">
  **Optional (required for browser automation).** A shared secret used to authenticate requests to the `/cdp/*` endpoints. All CDP requests must include `?secret=<CDP_SECRET>` as a query parameter.

  Generate a secure random value:

  ```bash
  npx wrangler secret put CDP_SECRET
  # Enter: $(openssl rand -hex 32)
  ```
</ParamField>

<ParamField path="WORKER_URL" type="string">
  **Optional (required for browser automation).** The public HTTPS URL of your deployed worker, for example `https://moltbot-sandbox.your-subdomain.workers.dev`. The CDP shim uses this to construct callback URLs for browser targets.
</ParamField>
