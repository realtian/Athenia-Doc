You can go from zero to a running personal AI assistant on Cloudflare's global network in under ten minutes. The steps below walk you through installing dependencies, wiring up your secrets, deploying the Worker, and opening the Control UI for the first time.

<Note>
  You must be on the **Cloudflare Workers Paid plan** ($5/month) before you begin — Sandbox containers are not available on the free tier. See [Requirements](/requirements) for the full list of prerequisites.
</Note>

## One-Click Deploy

If you prefer not to use the CLI, click the button below to deploy directly from the Cloudflare dashboard. You will be prompted to enter your secrets through the UI instead of the terminal.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/cloudflare/moltworker)

Otherwise, follow the step-by-step CLI instructions below.

---

## CLI Deploy

<Steps>
  <Step title="Clone the repository and install dependencies">
    Clone the project and install its Node.js dependencies with npm.

    ```bash
    git clone https://github.com/cloudflare/moltworker
    cd moltworker
    npm install
    ```

    This installs Wrangler (the Cloudflare CLI) and all other build-time dependencies. You need **Node.js 18 or later** — run `node --version` to confirm.
  </Step>

  <Step title="Set your AI provider API key">
    OpenClaw needs access to an AI provider to power your assistant. Anthropic's Claude is the recommended default.

    ```bash
    npx wrangler secret put ANTHROPIC_API_KEY
    ```

    Paste your [Anthropic API key](https://console.anthropic.com/) when prompted. If you prefer OpenAI, set `OPENAI_API_KEY` instead. If you want to route requests through Cloudflare AI Gateway (for caching and analytics), see the [AI Gateway setup](/configuration/ai-providers) guide.

    <Tip>
      You only need **one** AI provider key to get started. You can add more providers or switch to AI Gateway later.
    </Tip>
  </Step>

  <Step title="Generate and set your gateway token">
    The gateway token protects access to your Control UI. Generate a cryptographically random token and push it to Wrangler in one go — and save it somewhere safe, because you'll need it every time you open the UI.

    ```bash
    export MOLTBOT_GATEWAY_TOKEN=$(openssl rand -hex 32)
    echo "Your gateway token: $MOLTBOT_GATEWAY_TOKEN"
    echo "$MOLTBOT_GATEWAY_TOKEN" | npx wrangler secret put MOLTBOT_GATEWAY_TOKEN
    ```

    <Warning>
      Store the value printed by the `echo` command before continuing. You cannot retrieve it from Cloudflare after this step — if you lose it, you will need to generate and set a new one.
    </Warning>
  </Step>

  <Step title="Deploy to Cloudflare">
    Build the front-end assets and deploy the Worker in a single command.

    ```bash
    npm run deploy
    ```

    Wrangler will print your Worker URL when the deploy completes — it will look like `https://moltbot-sandbox.<your-subdomain>.workers.dev`. Keep this URL handy.
  </Step>

  <Step title="Open the Control UI">
    Navigate to your Worker URL and pass the gateway token as a query parameter.

    ```
    https://your-worker.workers.dev/?token=YOUR_GATEWAY_TOKEN
    ```

    Replace `your-worker` with your actual Worker subdomain and `YOUR_GATEWAY_TOKEN` with the token you saved in Step 3.

    <Note>
      **First request takes 1–2 minutes.** The Sandbox container needs to boot on the initial request. Subsequent requests are much faster. If you see a timeout, wait a moment and refresh the page.
    </Note>
  </Step>
</Steps>

## Before You Can Use the Control UI

Opening the URL above gets the container running, but **you cannot use the Control UI** until you complete two more one-time setup tasks:

<Warning>
  Skipping either step below will leave the Control UI inaccessible or your assistant unprotected. Complete both before inviting anyone else to use your assistant.
</Warning>

1. **Set up Cloudflare Access** — Cloudflare Access protects the Admin UI (`/_admin/`) and API routes from unauthenticated visitors. Follow the [Cloudflare Access setup guide](/configuration/cloudflare-access) to enable it on your Worker and push the two required secrets (`CF_ACCESS_TEAM_DOMAIN` and `CF_ACCESS_AUD`).

2. **Pair your device** — Even after Access is configured, your browser is treated as an unknown device until you explicitly approve it. Follow the [Device Pairing guide](/features/device-pairing) to approve your first device through the Admin UI at `/_admin/`.

Once both steps are done, your assistant is ready to use.
